Adapt the MySQL formatters to the expression / dialect split, where a probe answers whether a clause can be expressed and one parameter per spelling asks which one was requested: every two-spelling clause this backend consumes now reads both parameters (`with_validation` / `without_validation`, `restart_identity` / `continue_identity`, `cascade` / `restrict`, `deferrable` / `not_deferrable`, `wait` / `no_wait`, `enforced` / `not_enforced`, `initially_deferred` / `initially_immediate`), setting both sides of a pair is refused at construction with `ValueError`, and a request MySQL cannot spell raises `UnsupportedFeatureError` naming the requested spelling instead of rendering the statement as if the caller had specified nothing. `MySQLExchangePartitionExpression` is breaking: `with_validation` now defaults to `False` and the new `without_validation` defaults to `False`, neither set renders no validation clause, both set raises `ValueError`, and `WITH VALIDATION` is refused below MySQL 5.7 -- so a caller that passed `with_validation=False` to mean `WITHOUT VALIDATION` should drop the argument or pass `without_validation=True`. An identity request (`GENERATED ... AS IDENTITY`, bare or with `ALWAYS` / start / increment) now refuses by name instead of rendering a bare `AUTO_INCREMENT`. Qualified names are carried as `Table` / `View` catalogue objects, and a formatter handed the wrong kind raises `TypeError` naming the slot; the dialect's protocol bases follow core's split and renames (`ViewSupport` to `ViewObjectSupport`, `SequenceSupport` to `SequenceObjectSupport`, `SchemaSupport` to `NamespaceSupport`, `IndexSupport` to `IndexObjectSupport`, `TableSupport` to `TableObjectSupport`, and `UserDefinedTypeSupport` / `DomainSupport` to the per-statement create / alter / drop families), and `MySQLTableExpression` is renamed `MySQLTableStatement`.
