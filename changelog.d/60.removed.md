Remove `SequenceMixin` from `MySQLDialect`'s base list, because MySQL has no sequence object: `supports_sequence()` and the other inherited sequence probes are now absent rather than answering `False` -- a caller that asks gets `AttributeError` -- and `CreateSequenceExpression` / `AlterSequenceExpression` / `DropSequenceExpression` now raise `UnsupportedFeatureError` naming the dialect and the missing formatter from core's dispatch instead of rendering `CREATE SEQUENCE ...` SQL the server cannot run, which is what the inherited formatters did while the dialect's own probes said sequences do not exist. `SequenceNameMixin` stays, so a `Sequence` is still accepted as an identifier and `Sequence(dialect, 's').to_sql()` still renders. Remove the MySQL-specific `supports_auto_increment()` probe, superseded by `supports_auto_increment_column()`.
