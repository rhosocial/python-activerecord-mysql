Add `MySQLColumnTypeMixin` (`mixins/column_type.py`) — the column half of the rebuilt column-type protocol — composed into `MySQLDialect` alone, because core's `ColumnTypeMixin` has no inherited table for it to override and so its `MYSQL_COLUMN_TYPES` class attribute is the whole version-independent answer. Every one of the framework's common Python types is answered, the deviations from the portable baseline being `float` and `Decimal` both answering `NumericColumn` (core now models both width families with one column class, while MySQL's `DOUBLE` and `DECIMAL(p,s)` — distinct types with distinct rounding — remain two classes on the DDL side, which is where that measurement lives), the four containers answering `JSONColumn` rather than core's `ArrayColumn` (MySQL has no array type on any version, so a column cannot be declared `INT[]`, while the JSON path family is measured working from 5.7), and `timedelta` answering `NumericColumn` because MySQL's `INTERVAL` is an expression keyword and never a column type. The one version-dependent cell is `dict`, answered `None` below 5.7 — measured on 5.6.51, which has neither the `JSON` column type nor any JSON function (`1064` for the DDL, `1305 FUNCTION ... does not exist` for the operations), so a default there would render SQL the server refuses with the error pointing at the column rather than the annotation; the refusal instead fails at model-definition time naming `UseColumnType`, and the gate reads `MySQLJSONFunctionMixin.supports_json_path` rather than repeating `5.7.0` so the column-level answer and the expression-level one cannot drift, while the containers keep their `JSONColumn` answer below the gate because a sequence is not obliged to use the function family the measurement refuses. Add `MySQLTypeSupport` (`protocols.py`) stating the MySQL-exclusive type families — the `mysql_*` width names, signed/unsigned, the blob width family and the `BINARY(16)` UUID substitute — and declare `STRING_CONCATENATION = "CONCAT"` explicitly, because MySQL reads `||` as logical OR unless the server runs with `PIPES_AS_CONCAT`. Compose the four new node mixins `TrimMixin`, `LpadMixin`, `RpadMixin` and `RepeatMixin`: MySQL spells all four natively, so the shared default formatters are the answer and no override is needed. Add the tests that keep this from silently drifting — `test_mysql_column_type.py`, `test_mysql_uuid_substitute.py`, `test_mysql_enum_set_functions.py`, and an enumeration matrix over every core node class that requires a class to either render or be listed with a reason.
