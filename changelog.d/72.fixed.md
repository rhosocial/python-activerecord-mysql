Fixed `list_constraint_states()` on servers below MySQL 8.0.16, where `information_schema.CHECK_CONSTRAINTS` and `TABLE_CONSTRAINTS.ENFORCED` do not exist: the statement no longer names either, so 5.6 / 5.7 / 8.0.15 answer the primary-key, unique and foreign-key constraints they do keep instead of failing with `1109 unknown table`. The `information_schema` relations and columns this backend may name are now recorded per measured version in `impl/mysql/catalogue.py`, every introspection statement is built from that table, and an offline guard renders each statement for each recorded version and rejects SQL that names an object or column the version lacks.
