Stop dropping SSL/TLS settings when connecting to MySQL. `MySQLBackend.connect()` forwarded `ssl_ca`, `ssl_cert`, `ssl_key`, `ssl_verify_cert` and `ssl_verify_identity` unconditionally, so an unconfigured connection sent `ssl_ca=None` and an explicit `ssl_verify_cert=False` that overrode the driver's own defaults; those keys are now emitted only when actually set. The generic `ssl_mode` and `ssl_ciphers` fields have no mysql-connector-python equivalent, so rather than ignoring them silently they are now rejected by `MySQLConnectionConfig.validate()` with a pointer to the driver's `tls_versions` and `tls_ciphersuites` keywords, which are new config fields and are now forwarded to the driver.
