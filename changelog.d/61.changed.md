Move the `MySQLPartitionMixin` partition-metadata query off the removed operator sugar — a production fix rather than a test tidy-up, since `Column(...) == FunctionCall(...)` now evaluates to a Python `False` instead of a predicate and would have handed `where()` a value it rejects. The function factories (`bitwise.py`, `enum_set.py`, `json.py`, `math_enhanced.py`, `spatial.py`) lose their `_convert_to_expression` coercion entirely: a bare string used to become a column reference, so `FIELD("b", "a", "b")` did not report that "b" is the second value but read columns `a` and `b` and reported where their contents sat. Their arguments are now expressions — `NumericColumn` where a column is genuinely meant, `Literal` where a value is — and `find_in_set`/`field` say so in their signatures. Follow the DDL-source accessor migration: `column_type()` is now the declaration accessor and SQL-type reads go through `column_data_type()` / `columns_data_type()`. Rename `DateTimeColumn` to `TimestampColumn` throughout, as core did — the column layer models values, and `datetime` is a vendor spelling rather than a different value.
